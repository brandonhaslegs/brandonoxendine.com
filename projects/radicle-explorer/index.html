Radicle Explorer

Redesigning Radicle’s web explorer and website so they feel like the same product as the desktop app. Designed in the codebase and shipped as patches.

Role: Visual Design, Design System, Copywriting, Website, Code

Radicle is a way to collaborate on code without a central server. Repositories, issues and patches live on people’s own machines and replicate peer to peer, with always-on seed nodes keeping things available. Radicle Explorer is the web app for browsing what those seeds host. It’s usually the first thing someone sees of a Radicle project, often from a link somebody posted. The same repo also holds radicle.dev, the marketing site.

While I was redesigning Radicle Desktop, Explorer kept falling behind. A patch looked one way in the app and completely different on the web. So I took the same approach here: design in the code, ship patches, and let the maintainers review design decisions the same way they review everyone’s code.

Design system

Explorer moved onto the same design system as the desktop app, built on the new brand we developed with A Color Bright (there’s more on how the system works in the Radicle Desktop case study). Code blocks, READMEs and headers moved onto the new canvas color, the brand blue got simpler, and the favicon and app icons were updated. I also built a design system modal right inside the app, so anyone working on Explorer has one place to check which color token, type style or button to use, instead of guessing from whatever the last person did.

Patches that match the desktop app

The web patch page got rebuilt to match the new desktop one: a single column, one timeline of comments, revisions and reviews, and the metadata up top. To show the same lifecycle events as desktop (opened as a draft, archived, reopened), the web needed data it didn’t have, so the patch also adds a small endpoint to the server. Older nodes without it still render the page fine.

Comment threads got the desktop treatment too: replies indented in their own boxes, reactions with real emoji, and a copy link button on every comment. Open a link to a comment and it gets a ring in the brand color so you can find it.

Repo pages

The repo page stacked two rows of tabs with the repo header sandwiched in between. Now the repo header comes first and there’s a single row: Files, Commits, Issues, Patches, Releases.

Commits became a timeline like the desktop app’s. Since commits are already grouped by day, each row shows the time instead of another “21 days ago”, and hashes and times line up in a column on the right.

Every repo also got a readable identity document page: who the delegates are and how many of them have to agree before a change counts.

Profiles

A user page used to list the repos someone maintains and that’s it. Now it shows what they’ve actually done: every repo they maintain or contributed to, a contribution calendar, and a feed of their patches and issues across repos. This needed new server endpoints too, built so older nodes keep showing the old page instead of breaking.

Mobile

Lots of people open Explorer links on their phones, and the repo page wasn’t great there. The file list now shows inline instead of hiding behind a Browse button, the branch row stays on one line, the node picker stays visible, and the delegates info moved below the README where it’s out of the way.

The website

radicle.dev lives in the same repo, so it got patches too. The How it works page was a scrolling slide presentation that was hard to read and harder to link to. I turned it into a normal two column page with an illustration next to each idea.

I pulled the illustrations into their own component and gave each a small ambient animation. They switch off if you prefer reduced motion.

I also did a copy pass across the whole site (sentence case, clearer calls to action, and fewer em dashes), added staggered entrances when a page loads, and animated the sidebar sub navigation with CSS view transitions. Then I explored a Get started page, with a call to action in the header pointing to it.

I also explored a redesign of the node page, the landing page for a seed. The old one was a sidebar and a grid of cards. The new one explains what Explorer is for first-time visitors and gives the seed itself a real header.

My favorite exploration was a page about GitHub’s uptime. It charts GitHub’s own status page data since 2022, which adds up to more than 72 days of degraded or unavailable service. Radicle doesn’t have that problem, because there’s no server to go down.

What I took away

The web is where most people meet Radicle, and for a while it felt like a different product from the desktop app. Most of this work was closing that gap. It also taught me to design for nodes I don’t control: every new feature here has to degrade gracefully on seeds that haven’t upgraded yet, which is a very peer to peer kind of design constraint.
